# 账户适配库 · 0.12.1增量

适配导入预览不写入，确认后加入当前账户库并关联当前聊天。现有聊天专属配置可在同一入口一键供其他聊天复用。库保留不同版本；新聊天普通接入时自动使用精确原文及引文匹配的唯一适配身份之最新匹配版本；多个身份不自动选择，通用玩法照常。旧聊天有绑定时不自动升级/重新核对，玩家可按需打开高级管理查看更新。暂停词条和既有成果不由适配更新重新结算。

配置仍为staged，不启用生成或动态统计。账户库结构为schemaVersion=1、revision、configs数组，最多512个ID/版本组合且总计4000000字符；严格拒绝同版本不同内容及降级导入，破坏字段的更新待迁移。不支持可执行字段。库本身不放入聊天备份/正文；当前词条绑定仍包含完整配置，恢复聊天后可以再共享到库。

库复用当前账户的设置存储和本机检查点，独立读写并保留最新连接设置与API Key。普通getSettings不携带库，旧设置表单保存时合并最新库。支持navigator.locks时按账户串行更新，并在拿到锁时重查账户；无该接口时同步读取/写入提供尽力合并，不保证多窗口原子性。宿主设置保存沿用既有延迟保存接口，未宣称跨设备落盘已核验。

账户库与聊天存档不是跨存储原子事务。先保存库，再提交当前聊天；后者失败保留预览并明确提示库已保存，可重试关联。库失败不修改聊天。可选库损坏不阻断普通资源准备或通用词条接入，手动库操作仍报告错误，不静默清空。

# 可扩展词条接入协议 v1

本阶段只登记和预览配置。operations/records是后续生成与统计引擎的声明，不是已实现机制，不修改既有统计结构或正文注入。没有自动调用AI、下载资源、执行脚本或写变量。入口：打开聊天并选择已接入词条，在“管理与备份 → 词条适配配置”导入JSON、核对、确认。

## 身份与原文

适配ID采用作者命名空间.固定词条ID，如original.echo_compass，改名和文件名变化不改此ID。聊天原power.id、档案ID、历史与余额不替换。适配ID不是世界书条目跨书合并的授权；现有导入依旧按世界书身份注册，不自动把同名条目合并。第一阶段适配保存在当前聊天的词条中，随档案备份；账户级配置库与自动关联将在后续阶段接通，当前不会跨聊天自动安装。

原文使用primaryRules的精确hash匹配，最多声明16个版本，不能只凭名称套用。该hash用于一致性核对，不是数字签名或作者认证。附加规则变化也会使绑定待核对；相同配置可再次预览确认。生成引擎后续必须读取当前完整规则，适配文本不能覆盖世界书限制。

## 顶层格式

- format固定为wjwk-adapter，schemaVersion固定为1。
- id为作者命名空间.固定词条ID，version为数字三段，如1.0.0，不接受前导零或预发布标记。
- name与description供玩家预览。
- target.primaryHashes保存原文指纹；作者可在接入口折叠的作者信息中读取。
- operations为1—12项，records为1—16项；原始文件最多512KB，配置最多128000字符。
- 所有对象严格拒绝未知字段；不支持script、HTML模板、URL加载器、事件代码、表达式或变量路径。

## operations

每项包含id、kind、label、instruction、ruleQuote、output、recordIds。id在本配置内固定且唯一；kind为create/plan/investigate/develop/transform/simulate/negotiate/arrange之一。output为design/plan/information/options之一，均是待正文处理的结果，不表示获得成果。ruleQuote为6—1200字、逐字存在于主词条的依据。recordIds必须引用已声明的统计对象。instruction最多4000字符，是生成要求的数据；不作为可执行代码。

## records

每项包含id、label、description、fields。每个字段包含id、label、type、description。记录及字段ID使用小写英文字母开头，随后字母/数字/下划线/连字符，最多64字符，禁止constructor/prototype/__proto__。每类最多16字段。本协议第一版只接受text，保留数量、单位、限制原文，不做数字转换或汇总。对象实例的稳定ID、设计状态与成果状态将在统计引擎阶段接通，不以类型ID代替对象ID。

## 更新与兼容

数字比较版本，1.10.0高于1.2.0。不接受降级、同版本改内容或用另一个适配ID覆盖原适配。相同原文及同版本同内容无需重复保存。可增加统计对象/字段、调整说明；删除对象/字段或改型先拒绝，直到另有明确迁移方案。改字段ID等同删除旧字段，不能作为普通重命名。已有数据不静默丢弃。

绑定包含完整配置、配置摘要、原文及完整规则版本、登记时间、staged状态和最多32条旧版本元数据。摘要用于一致性检查，不提供来源认证。旧存档没有此字段仍可用；原文变化时保留旧绑定并标记待核对，不静默套用。后续账户级适配库不得静默覆盖当前聊天固定版本。

## 测试素材与后续门

data/adapter-example-worldbook.json为两条自编新词条；对应echo与artisan适配包仅示范接入格式，不代表真实武库机制适配。开发时未内置这些词条名称也可导入预览、登记、版本更新并恢复备份。真实额外AI生成、正文承接和成果归档尚未接通，不能用配置成功代替这些验收。

后续顺序：账户级适配库与导入关联 → 多类词条配置迁入 → 操作台生成与正文注入 → 动态成果记录/迁移 → 特殊机制覆盖。每阶段单独验证和交付。

## 0.12.4 统计语义

当前内置7种适配，新增4种均只采用现有records/operations声明，无新宿主API。record.description定义对象身份与完成边界，field.description定义已知情况和限制；后续扩展仍可用账号适配导入。active表示相应对象或记录已成立，不能跨层解释为情报机缘已获得、模拟奖励回流或诺契已付。条件、现实兑现和局部控制范围在独立字段中保留；插件不能靠字面引用验证所有语义，真实模型理解仍是验收边界。旧三类配置保持相同内容与指纹；现有账号绑定仍优先。

## 0.12.5 可选成果总览

适配配置可新增dashboard:{title,summary,sections:[{id,label,description,recordIds}]}。title/label最多100字，summary/description最多400字，1至16个模块；模块ID唯一，recordIds引用已声明records且跨模块不重复。没有分配的统计分类仍按普通专用档案展示，旧配置完全可用。模块只读取当前同adapterId档案，失效来源单独标记且不计现状，ended折叠保留。每模块预览两项对象，其余可展开；详情、历史与正文记忆仍是原同一档案。需要插件0.12.5或以上，旧插件拒绝未知字段，不能宣称向下兼容。

模块统计是对象条目数，不是人口、库存或贡献合计。成员、产线、库存、小源/大源之间的联系目前保留为正文确认的文字，没有自动依赖图、引用完整性或算术结算。新dashboard配置不增加宿主API、后台服务和模型请求。

## 0.12.10 成长、变形与交换统计

本批仍是schemaVersion=1数据定义，不增加导入格式或宿主API。六项精确匹配适配由records/operations/dashboard定义；21个模块全部复用既有AI整理、计划与档案界面。

同一目标、形态或资格更新应提供既有稳定ID；点石成金的新客观框架序列另建记录以保留旧框架，不靠改名刷新；整体与局部要有独立结构意义。上位替代候选及生命球未化身定义用planned，候选采用或不再需要后结束，不能把候选算入已得结果。生命库中非当前形态仍可active并保留成长。

升变单槽是当前任务档案，剧情进度和保留等待使用明确文本，浏览器刷新不推进任务；点数余额快照不是收入。归我所有同场即时改选更新所得而不重复发，已取部分和对手新成长分别记录。等价交换暂存是已成立资格，实体到手需实际交割；交割后更新原暂存为ended，关联原交换和真实成果。

这些规则由AI的schema/instruction引导，现有校验负责结构与来源，不做世界规则推演、数值求和、剧情时钟、跨档案自动级联或真假语义判断。模型应为同次变化提出必要的各条档案更新，例如形态切换需同步当前形态和入库形态。固定响应测试不证明真实模型必然正确。

## 0.12.11 奖励、独立来源与长期收藏

schemaVersion仍为1。本批六项28模块只新增数据定义，无宿主API和导入格式变更。prototype为协议禁用标识符，原型实体引用字段使用prototype_ref。

签到周期须真实有效经历，日常/场景/节点及里程碑独立；仓库领取不新发原奖励。抽奖按角色连续24小时日程，不能按设备时钟、换历法或时间往返刷新，旧日余次先抽取后新日五次；特权同核心进化更新原ID，奇物封存到最终释放前仍持有。

攻略每目标的当前好感、历史已领10%区间与20%阶段分开；旧阈值回升不领新奖，所得不因下降撤回。点数全局库存仅采用正文明确余额和流水，不自动定价、奖励或扣点。

投资每笔独立史线从原祖史出发，首次类别复制资格跨笔跨线持续；当前家族来路与资产只承接真正当代有效部分。历史失落资产仅历史，互斥版本不能并列为当前持有。

同时穿越共有能力源于实际取得，能量只确认独立容量来源、共同完整上限和各我存量，不将共享上限再次计入来源；物品真实转移更新原档案。幻想具现区分原型、实体、匹配技艺、自身沉淀、专属版本和独立新神话；损毁实体不删除原型。

以上为模型语义提示，结构校验不是世界规则推演。多档案同时变化需模型提出相关多条更新；插件不会从单条字段自动计算奖励、容量、日程、首次资格或跨档案状态。固定响应测试不证明真实模型必然正确解释原文。
