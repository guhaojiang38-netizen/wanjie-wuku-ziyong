# 0.12.22 整理可靠性与运行日志

## 玩家使用

连接设置 → 运行日志；桌面侧栏管理与备份中也有入口。默认自动记录，无需填写。

日志包括版本、任务名称、耗时、读取楼层与偏移、原始/实际读取字符数、思考/状态/选项/变量块统计、附加世界书条目摘要、模型请求与返回大小、校验失败引文、有效项和保存结果。它和聊天成果档案分开，保留本浏览器当前账户最近40次任务，约90万字符容量；存储失败时退回内存并提示。

遇到难以定位的问题时，开启“临时记录请求与返回”，重现一次，再导出日志 JSON。开关只对之后开始的任务生效，刷新后恢复关闭。每段详细请求/返回最多100000字符，超出明确标注。导出前可展开检查；详细记录可能包含私人剧情，常见凭据和当前API Key会脱敏。

## 整理行为

- 新来源格式 archive-read-v2 保留正文、正式结算及带标签的 WJWK-status 快照；排除已标记的思考、选项、变量指令。支持带/不带波浪号的 konatan_planning、缺开标签但保留关闭分隔符的规划前缀、嵌套及未闭合思考块。
- 状态快照明确作为同一回复的状态参考，提示 AI 优先引用正文，不将“当前安排/计划/准备”当作已完成成果。世界书仍只是参考设定。
- 每条成果、安排进展、拟定进展分别通过原有严格校验；不支持的引文、失效来源等列为未通过项，有效更新可单独保存。重复且冲突的同一对象整组排除，不选择其中一项。
- 有失败项时，本批楼层保守地留待重查，避免失败项随着游标推进而永久丢失；自动整理不会在同一批未推进时无限重试API。有效项重查沿用去重规则。
- 整批格式非法或数量越界仍整体拒绝，不将异常输出伪装成无变化。没有任何有效更新时，不出现“确认无变化”按钮，不推进读取进度。
- 旧 settlement-v1 / 无 format 的档案与游标按原算法核对，不批量重算来源。旧楼层进入新版整理范围时可能重新核对一次。
- 修复的是状态区域漏读与整批中断；超出读取范围、被模型改写或不存在的引文仍不能记账。

## 边界与证据

724 项本地测试通过。模拟酒馆浏览器验证普通读取、新增世界书选择回归、漫漫长路部分保存、日志导出/脱敏/刷新保留与390px页面；用户提供的回复离线回放证明两段状态引文现在可读取，规划内容已过滤。

没有真实模型调用，没有写入真实酒馆。实际模型提取质量、第三方插件组合和手机真实浏览器仍需玩家验收。日志不自动上传给作者，不随聊天成果备份导出。
